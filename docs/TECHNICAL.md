# dsh-glaze — 毛玻璃外观插件

给 **DeepSeek Harness** 换一张自己的背景图，并调节界面的透明程度。

> **名字**：glaze 是「给器物上一层玻璃釉」。这里指的是把整个窗口罩在一层真实的磨砂玻璃
> 后面——壁纸从玻璃里透出来，而不是简单把底色调淡。
> 插件在设置页里的入口叫「外观」。

- 🖼️ **自定义背景图** — 支持 PNG / JPEG / WebP / GIF / AVIF / BMP / SVG，单张最大 32 MB
- 🫧 **界面透明度** — 0–100% 连续可调，背景图透出多少由你决定
- 🌫️ **背景模糊** — 让背景图柔化，文字更清晰
- 🎚️ **明暗遮罩 / 整体压暗** — 亮色背景图也能保证可读性
- 📐 **填充方式 / 对齐位置** — 铺满、完整显示、原始尺寸、平铺
- 👁️ **实时预览** — 设置页里直接看到叠加效果，改完立即生效
- 💾 **本机持久化** — 图片存在本地配置目录，设置写入 profile，重启后依然生效
- 🧊 **毛玻璃前景层** — 输入框卡片、其上方的任务/队列条、对话滚动区与侧边栏都带真实
  磨砂，滚动时下方文字**不会透上来**（见下文「为什么需要毛玻璃」）
- ⚡ **拖动手感** — 滑杆调整是单变量写入 + 逐帧合并，实测帧时间中位数 4.3ms
- 🌗 **跟随亮/暗主题** — 切换主题时背景遮罩与界面底色自动适配

## 快速开始

### 方式 A：作为本地插件安装（推荐）

```powershell
# 1) 把插件挂进 desktop profile（软链接，不复制）
cd $env:USERPROFILE\.dsh\profiles\desktop

# 在 package.json 的 dependencies 里加一行：
#   "dsh-glaze": "link:C:/path/to/dsh-glaze"
# 在 dsh.profile.bundles 数组末尾加：
#   "dsh-glaze"

# 2) 让 pnpm 建立链接
pnpm install

# 3) 重启 DeepSeek Harness
```

也可以直接用 Harness 自带的插件管理器/CLI：

```powershell
dsh plugin --profile desktop add C:\path\to\dsh-glaze
```

### 方式 B：作为独立包目录

把仓库放到任意位置，然后按方式 A 用 `link:<仓库根绝对路径>` 挂进 profile。
插件不需要构建步骤——`index.js` 和 `client.js` 都是可直接加载的 ESM / 浏览器 bundle。

## 使用

1. 打开 **设置**（`Ctrl+,`，或点左下角「更多」→ 设置）
2. 左侧导航选择 **皮肤**
3. 点 **选择图片…** 挑一张背景图
4. 拖动滑块调节效果，界面会立即变化

| 选项 | 作用 | 默认值 |
|---|---|---|
| 启用皮肤 | 关闭后恢复原版外观，但保留图片与数值 | 开 |
| 界面不透明度 | 100% = 完全不透明（原版）；越低背景图透出越多 | 45% |
| 背景模糊 | 模糊界面后方的背景图 | 10px |
| 背景明暗遮罩 | 背景图与界面之间、与主题同色的遮罩，保证文字可读 | 15% |
| 整体压暗 | 额外一层黑色遮罩，适合很亮的背景图 | 0% |
| 填充方式 | 铺满（裁剪）/ 完整显示（留边）/ 原始尺寸 / 平铺 | 铺满 |
| 对齐位置 | 居中 / 顶部 / 底部 / 左侧 / 右侧 | 居中 |

> **想要背景图更明显？** 把「界面不透明度」降到 20–35%，同时把「背景明暗遮罩」降到 5–10%。
> **文字看不清？** 提高「背景明暗遮罩」，或增加「背景模糊」。

## 工作原理

插件分两半，通过 Harness 自己的插件机制协作：

### Host 半边 (`index.js`)

- **背景图存储** — 图片写到 `$DSH_HOME/dsh-glaze/wallpaper.<ext>`，旁边放一个
  `meta.json` 记录原始文件名、MIME、字节数和 revision。故意不存进 settings：
  settings 是 JSON，几 MB 的 base64 会让每次 `settings.describe` 都变胖。
- **HTTP 路由** — 浏览器半边通过它们读写图片：

  | 方法 | 路径 | 作用 |
  |---|---|---|
  | `GET` | `/dsh-glaze/state` | 廉价的状态（无图片字节），供轮询 |
  | `GET` | `/dsh-glaze/image` | 背景图字节（URL 带 `?v=<revision>`，可长期缓存） |
  | `POST` | `/dsh-glaze/upload` | 上传背景图（原始图片 body） |
  | `DELETE` | `/dsh-glaze/image` | 清除背景图 |

  路由**不受 `/api` 认证保护**（Harness 的 webserver 本身不认 auth），所以插件自带
  一层浏览器信任围栏：只接受 loopback / `webStartup.trustedHosts` 权威，拒绝
  `sec-fetch-site: cross-site`，`Origin` 必须同名（并放行 Electron 外壳的
  `dsh-app://app`）。这是防 DNS-rebinding / 跨站的，不是认证。
- **配置 schema** — `Config` 的每个字段都是 `.volatile()`。这一点是硬性要求：
  Harness 的 settings 只会把 volatile 字段投影成可编辑表单，非 volatile 字段的滑杆
  会**看起来能动、实际存不下去**。
- 关掉自动生成表单（`settings.configure({ auto: false })`），否则设置页会出现两份。

### Client 半边 (`client.js`)

- **壁纸** — 作为 **`<body>` 自己的背景**（`background-size: cover`），不是单独的
  `z-index:-1` 图层。原因见下文「壁纸为什么看不见」。
- **一整层毛玻璃** — 整个窗口只铺**一张**磨砂层，压在壁纸和界面之间；不再分列做。
  原因见下文「为什么改成整窗一层玻璃」。
- **结构容器清底** — 按尺寸识别外壳的大容器并清掉它们的实心底色，否则玻璃被盖住。
  原因见下文「为什么侧边栏会时有时无」。
- **毛玻璃开关** — 设置页「毛玻璃效果」。关掉后磨砂层退化成纯半透明底色（完全没有
  `backdrop-filter`），更省、也不会出现模糊相关的接缝。
- **对话框** — 设置等弹窗挂在 `document.body`、在 `#root` 之外，插件用
  `--dsh-glaze-dialog-fill` 把它固定成实色，任何透明度下都可读。

### 为什么左侧没有分隔线（v0.15 修的坑）

现象：右侧面板和主体之间有一条清晰的分隔线，左侧侧边栏和主体之间却没有，整块界面看起来「左边缺一条」。

用截图按列统计平均亮度量出来的数据：

| 边界 | 亮度差（0–255） | 结论 |
|---|---|---|
| 左侧（侧边栏 / 主体） | **0.03** | 完全看不出线 |
| 右侧（主体 / 右侧面板） | **+40**（96 vs 56） | 一条明显的**亮**色发丝线 |

原因是外壳给侧边栏列画的是 `border-right: 1px solid rgba(0, 0, 0, 0.12)`——一条 **12% 黑线**。
浅色主题下这条线刚好（实测 19/255 的暗线，正常可见），但深色主题下它落在深色玻璃上，
几乎与背景同色，于是「消失」了。而右侧那条用的是浅色线，所以深色下反而更清楚。

修法：插件按结构位置找到侧边栏列，重新声明这条线，颜色跟着主题走——

- 浅色：`rgba(0, 0, 0, 0.12)`（与外壳原值一致，像素级不变）
- 深色：`rgba(255, 255, 255, 0.20)`（对齐右侧那条亮线的强度）

验证：浅色仍是 19.46（未变），深色从 0.03 变成 **+44**，与右侧的 +40 基本一致。

### 为什么关掉毛玻璃，重启后又自己开了（v0.13 修的坑）

这个现象有**两个独立原因**，只修一个还是会复现：

**原因一：我的维护脚本覆盖了用户设置。**
`tools/reset-live-settings.mjs` 会把整份配置重写成硬编码默认值，而我在每次收尾时都运行它，
于是用户改过的开关（最明显的就是毛玻璃）被悄悄改回默认值。

现在该脚本已被 	ools/check-live-settings.mjs 取代：**默认只读**，只报告哪些字段缺失或非法；
要写入必须显式加 --force，而且只补缺失/非法项，**绝不覆盖已有有效值**。

**原因二：客户端启动时没有读回持久化配置。**

启动路径只调用了一次 `adoptFromForm()`。配置表是异步就绪的，此刻 status 往往还不是
eady，这次读取**静默失败**，插件就用 schema 默认值绘制，之后再也不重试——
所以无论怎么关，重启后都回到默认值。

修法：

1. **订阅配置表**（configForm.subscribe），任何一次变为 ready 都会被采纳并重绘。
2. **启动后有限重试**（50ms × 40 ≈ 2 秒），覆盖配置表始终不发通知的情况；成功后立即停止，
   不留常驻定时器。

审计中新增一条守卫：关掉毛玻璃 → 刷新页面（等价于客户端重启）→ 断言仍然是关闭状态。

### 为什么关掉皮肤后恢复不了原版（v0.11 修的坑）

关闭皮肤后界面仍是「被压了一层」的样子，必须重启才能恢复。

原因是三个辅助图层（壁纸玻璃层、遮罩、压暗）的样式写成了**没有作用域**的
`#dsh-glaze-pane { ... }`。关闭皮肤时只是移除了 `html` 上的激活标记、并按 `on === false`
跳过了后续绘制，但那几个元素仍留在 DOM 里、样式照常命中——于是整窗继续被半透明盖着。

修法两条一起上：

1. **所有图层规则都加 `html.dsh-glaze-active` 前缀**，标记一没，规则全部失效。
2. **关闭走完整拆除** `paintOff()`：移除激活标记 → 删除三个图层节点 → 删除生成的清底
   规则 → 清掉 `body` 上的内联变量与壁纸。插件卸载 `unpaint()` 复用同一函数，避免两条
   路径逐渐走偏。

审计里为此加了 5 项断言，现在都通过（关闭后玻璃层不存在、壁纸已移除、内联变量清空、
辅助图层全删、外壳表面恢复为 `rgb(249,250,251)` / `rgb(255,255,255)`）。

### 为什么改成整窗一层玻璃（v0.5 修的坑）

v0.3 的做法是给三个列分别做磨砂，有两个硬伤：

1. **顶部标签栏不在任何一列里**，所以它完全没有玻璃，壁纸直接透在文字后面。
2. **三个分别磨砂的矩形有三套边缘**，看起来像三块面板拼在一起，不像一层皮肤。

改成整窗一张玻璃后，顶部、侧边栏、主区共用同一套模糊和色调——没有接缝、没有色差。

v0.8 起**彻底移除了「作用范围」选项**，玻璃层固定覆盖整个窗口。原因有两个：

- 局部玻璃会在标题栏中间留下一条可见的硬边，怎么调都不如整窗好看。
- 它带来一整类几何 bug：玻璃层要跟着侧栏/主列的尺寸反复测量和重定位，容易滞后于
  布局变化或对不齐。固定成整窗后，这个环节整个消失。

### 为什么底部状态条像一块浮起来的白块（v0.8 修的坑）

输入框下方那行状态（轮次、token、缓存命中）是一条较窄的短横条。此前的识别条件只覆盖
「整列」和「整幅宽条」，它两边都不沾，于是保留了自己的不透明底色，在玻璃上看起来像
一块浮起的白色卡片。

修法：增加一条**底部带**识别——位于窗口底部 150px 内、高度不超过 130px、宽度达到窗口
20% 的元素，视为外壳 chrome 并清掉底色。实测注入一条白色横条后，它会从
`rgb(255,255,255)` 变为透明，文字直接落在玻璃上。

（清掉那层不透明底色之后，这行字又变成「悬在玻璃上」，所以 v0.9 给它补了一个胶囊底，
见下一节。）

### 底部统计条为什么反复「怪怪的」（v0.12 彻底修）

这一块改了很多轮都不满意，最后定位到两个具体的成因，都跟「容器」无关，而是**多余的效果层层叠加**：

| 多余的东西 | 造成的现象 |
|---|---|
| 胶囊上的 `backdrop-filter` | 它坐在玻璃层之上，而玻璃层已经模糊过一切；再加一层滤镜只会新建一个合成层，边界在浅色背景上显出一条淡淡的矩形光晕 |
| 胶囊上的 `border` / `box-shadow` | 把胶囊从玻璃上「描」出来，看着像临时塞进缝里的独立小盒子 |
| 统计条目自己的内层底色 | 外壳把两个条目套了好几层，某些层的 hover/胶囊底色没被压平，于是变成「框中框」 |

现在胶囊只剩**一层扁平的半透明填充**：无滤镜、无描边、无阴影，内部所有层级的底色 / 边框 / 阴影统一压平。

验证方式也换了：用一张高对比壁纸 + 三层嵌套、每层都带自己底色的复刻结构，确认内部底色全部为透明（gba(0,0,0,0)）、滤镜与阴影均为 one，才认为干净。

### 为什么底部状态行像「乱拼凑」（v0.9 修的坑）

输入框下方那行统计（轮次 / tok/s / token / 缓存命中）在 Harness 里是
`conversation.composer.dock` 插槽的两个条目（`activity` 与 `usage`），
**本身没有容器底色**——它直接把自己的文字画在布局背景上。

默认外观下这没问题，因为背景就是一块完整的侧栏/主区底色。但套上皮肤后，输入框是一块
白色圆角卡片，下面那几个数字就悬在玻璃上，两者没有任何视觉关系，看起来像临时拼上去的。

修法是给它一个**自己的胶囊底**：居中、全圆角、半透明（与玻璃同调）、一条极细描边，
内部条目一律透明，保证只有一层表面。这样它就从「飘在缝里的文字」变成「输入框下面的
一条统计条」。

（另外 `[data-queue-dock]` 不同：它要盖住滚动内容，所以保留接近实心的底色。）

### 为什么侧边栏底部会有一条突兀的横带（v0.6 修的坑）

侧边栏滚动区底部有一个「渐隐」遮罩，它的渐变终点是**不透明的调色板底色**
（深色主题下是 `rgb(27,27,28)`）。容器被清成透明之后，这个不透明终点就变成了一条
生硬的彩色横条——看起来像没擦干净的一道白边。

修法：把这类遮罩改成渐变到透明（`background-image: none`），柔化效果保留，色阶消失。

### 为什么侧边栏会「时有时无」（v0.6 / v0.7 修的坑）

这个问题有**两层**原因，只修掉一层就会复现，所以两轮才彻底解决。

**第一层：一次性扫描的竞态。**
外壳的侧边栏根节点和标签栏宿主是在皮肤首次绘制之后才挂载的，扫一次必然漏掉它们，
侧边栏就保持不透明，直到下次导航碰巧重新扫到。

**第二层（更隐蔽）：判断条件把自己算了进去。**
当时「要不要清这个容器」是靠**读它的计算背景色是否不透明**来决定的。可是清掉之后，
它算出来就是透明的 → 下一轮扫描判定「不需要清」→ 删掉规则 → 它又变回不透明。
这是一个自我引用的循环，表现就是隔一段时间自己恢复原样。

最终修法两条一起上：

1. **只看几何，不看颜色。** 清一个本来就透明的容器是无副作用的，所以判断条件只保留
   「是不是又高又宽的结构容器」。
2. **规则按结构位置生成，不再往 DOM 上打标。** 清底规则写进一张独立的样式表，选择器
   是 `#root > :nth-child(k) > …` 这样的位置链；React 重新渲染即使重建了节点或覆写了
   `className`，规则依然命中。DOM 变化时（防抖到一帧一次）重新生成，因此任何时刻挂载
   的容器都会被覆盖，没有时间窗口。

顺带记录几个被否掉的极端方案，避免以后再走回去：

| 方案 | 问题 |
|---|---|
| 按 CSS-module 类名点名清理 | 类名是每次构建都会变的哈希，漏掉标签栏宿主和侧边栏根节点 |
| 给元素打 class 标记 | React 重新渲染会覆写 `className`，标记被抹掉 |
| 把 `#root` 内所有元素都清成透明 | 连**输入框卡片、消息气泡、代码块**的底色也清了 |

可行的组合是：几何识别结构容器 + 位置选择器 + 排除内容区
（`[data-conversation-scroll]`、`[data-composer-*]`、菜单、弹窗）。代码块往往又宽又高，
如果只按几何判断会被误清，所以内容区必须整块排除。

### 壁纸为什么看不见（v0.3 修的坑）

最初把壁纸放在 `position:fixed; z-index:-1` 的独立图层上，结果**怎么调都不显示**。
两个原因叠加：

1. **`backdrop-filter` 采样的是元素「下面已绘制」的像素**。`z-index:-1` 的定位层不在
   这个采样面里——过滤器看到的是透明的根画布，所以毛玻璃渲染成一块死板的色块，
   壁纸既没被模糊、也没被看见。
2. **shell 的 frame 自己画了一层不透明底色**（就是 `--dsw-alias-bg-base` 落地的那个
   元素）。哪怕 `html/body/#root` 都透明了，这一层仍然把壁纸盖住。

修法：壁纸改成 `body` 背景（进入页面自身绘制顺序，正好在 `#root` 之下，也就是
`backdrop-filter` 的采样面），并把沿途会画不透明底色的结构容器清掉。

### 为什么不再逐个 token 调透明（v0.3 修的坑）

v0.2 把 22 个设计 token（`--dsw-alias-bg-layer-1` 等）整体 `color-mix` 成半透明。
问题是这些 token **是共用的**：同一个 `--dsw-alias-bg-layer-1` 既铺一整个面板，
也画一个 32px 的按钮。于是界面上每个小控件都变成深浅不一的透明补丁，整体看起来
「脏」且不统一。

现在只对结构层做一次毛玻璃，其余控件保持原样——一整块玻璃 + 清晰的控件，
视觉上干净得多，而且 `backdrop-filter` 只作用在几个大矩形上，不会产生小元素那种
硬边亮块。

### 为什么拖动不卡（v0.2 修的坑）

初版每次 `input` 事件都对 22 个 token 逐个 `getComputedStyle()` + 写内联样式，
每个 token 都是一次强制同步重排——拖动时必然掉帧。现在：

1. 所有玻璃参数都从 **几个 CSS 变量**（`--dsh-glaze-pane-opacity` 等）解析，
   拖动时只写这几个变量，不再逐节点改样式、也不再调用 `getComputedStyle`。
2. 重绘用 `requestAnimationFrame` 合并，一帧最多一次。
3. 写回 Host 用 120ms 防抖，拖动过程中不再发起几十次 RPC。

实测（60 次连续 input 事件）：帧时间中位数 **4.3ms**，p95 **5.2ms**，最大 6.9ms——
远低于 16.7ms 的一帧预算。

### 前景层不叠字

输入框卡片和它上方的任务/队列条正好叠在滚动内容之上。它们**位于滚动容器内部**，
Chromium 不会为它们采样滚动层里的兄弟内容，所以 `backdrop-filter` 在这里不可靠——
必须用接近实心的填充（≥92%）彻底挡住，滑杆怎么调都不会低于这个下限。

### 为什么滑杆「不灵敏」（v0.10 修的坑）

有一版为了「保证文字可读」，把「界面不透明度」压缩映射到 **62%–94%**，并给模糊加了
12px 硬下限。结果：

- 底色 62% 起步，壁纸几乎被盖住 → **开不开毛玻璃看起来没区别**
- 滑杆大半行程落在被夹掉的区间 → 拖动毫无反应
- 用户的原话是「毛玻璃效果不太灵敏」

问题出在把「防呆」做过了头。现在改为：

| 参数 | 计算方式 | 说明 |
|---|---|---|
| 窗口填充 | `22% .. 92%`（随不透明度线性） | 全行程有效，默认 35 → 47%，壁纸清晰可见 |
| 模糊 | `0 .. 60px` 直通 | 保留完整行程 |
| 极端角落保护 | 填充 < 35% 时模糊至少 16px | 只兜住「几乎全透 + 无模糊」这一个坏组合 |
| 输入框卡片 | 固定 96% | 必须盖住滚动内容，不参与调节 |

默认填充从 73% 降到 47% 之后，毛玻璃的开关与模糊滑杆都有肉眼可辨的变化。

### 设置项怎么验证的（`harness/audit-settings.cjs`）

只靠肉眼调参数反复踩坑，所以补了一个**端到端审计**：它驱动真实的设置控件
（开关 / 滑杆 / 下拉），等绘制稳定后读回浏览器实际计算出的值，覆盖整条链路
`控件 → update() → runtime.settings → paint() → CSS 变量 → computed style`。

```powershell
node harness/audit-settings.cjs     # 24 项，逐项打印实际值
```

当前结果：**24/24 通过**，包括「关掉毛玻璃后 `backdrop-filter` 确实变成 `none`」、
「不透明度 0→100 时填充从 22% 变到 92%」、「关闭皮肤后标记与清底规则全部回滚」等。

### 为什么必须跑 `smoke-client`

`node --check` 只验证语法。有一次 CSS 模板字符串因为注释里的一个反引号被**提前
闭合**，剩下的样式表被当成 JavaScript 解析，模块加载器报
`dsh-glaze: import failed: data is not defined` —— **整个插件静默不加载**，
界面上看到的只是「没有皮肤 + 一层壁纸」。这种「语法合法、导入即崩」的问题必须真
跑一遍才能发现。

`tools/smoke-client.mjs` 用最小 React/DOM 桩真正执行 factory + `apply(ctx)`：

```powershell
node tools/smoke-client.mjs     # CSS 模板完整性 + factory 执行 + apply 注册
node test-host.mjs              # Host 半边，29 项
```

## 文件结构

```
仓库根 = 包根（package.json 必须在这一层，git 安装才能解析到）
├── package.json        # dsh.bundle.patch + dsh.client 声明
├── cordis.patch.yml    # Host 行（id: dsh-glaze）+ 默认配置
├── index.js            # Host 半边：存储 + HTTP 路由 + Config schema
├── client.js           # Client 半边：壁纸 + 结构毛玻璃 + 设置页
├── icon.svg
├── preview.png         # npm 页面预览图
├── test-host.mjs       # Host helper 的单元测试（29 checks）

tools/
├── smoke-client.mjs    # 客户端导入期冒烟测试（必跑）
├── repro-import.mjs    # 复现「导入即崩」并定位到源码行
└── …                   # 其余为一次性迁移脚本，见 tools/README.md
```

## 开发

```powershell
cd plugin
node test-host.mjs        # Host 半边单元测试，29 项
node --check index.js     # 语法检查
node --check client.js

cd ..
node tools/smoke-client.mjs   # 【必跑】客户端导入期冒烟测试
```

改完 `client.js` 后无需重新构建——Harness 的 HMR 会通过
`/plugins/events`（SSE）热替换客户端 bundle；`cordis.patch.yml` 的改动能热加载。
只有**安装/替换整个包**（`pnpm install`）才需要重启。

## 已知限制

- 背景图按配置目录存一份，多 profile 之间不共享。
- 图片在浏览器里按 `cover/contain` 布局，不做多显示器分别设置。
- 透明度是通过 `color-mix` 实现的：需要 Chromium 111+ / Firefox 113+（Harness 桌面端
  自带 Electron，满足要求）。
- 不是主题替换：插件只调整「界面表面的不透明度 + 背景层」，配色仍跟随 Harness 的
  亮/暗调色板（因此切主题不会串色）。
